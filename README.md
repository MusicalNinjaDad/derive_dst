# derive_dst

`#[derive(DST)]` for `#[repr(C)]` structs whose **last field is an unsized slice** (`[T]`),
typically to mirror a C/C++ "flexible array member" struct such as
[`SP_DEVICE_INTERFACE_DETAIL_DATA_W`](https://learn.microsoft.com/en-us/windows/win32/api/setupapi/ns-setupapi-sp_device_interface_detail_data_w).

The derive generates:

- **`new(size: usize) -> Result<Box<Self>, InvalidFoo>`** — an allocating constructor which
  validates the requested size, allocates a zeroed buffer of the correct layout, initialises
  every sized field with its declared default (`field: Type = expr`) and returns the value boxed.
- **`layout_for(size: usize) -> Result<(Layout, usize, usize), InvalidFoo>`** — a layout
  constructor returning the [`Layout`], the byte offset of the unsized tail and the number of
  tail elements for a buffer of `size` bytes.
- **`InvalidFoo`** — a dedicated error enum (named `Invalid` + the struct name) with variants
  `InvalidLayout(LayoutError)` and `InvalidSize { requested, valid }`, implementing `Debug`,
  `Clone`, `PartialEq`, `Eq`, `Display`, `Error::source` and `From<LayoutError>`.

## Example

### Before (hand-written, e.g. in `redbook`)

```rust,ignore
#[repr(C)]
pub(crate) struct DeviceDetails {
    cbSize: u32,
    DevicePath: [u16],
}

impl DeviceDetails {
    pub fn new(size: usize) -> Result<Box<Self>, InvalidBufferSize> {
        let (layout, offset, num_words) = Self::layout_for(size)?;
        let rawu8 = match Global.allocate_zeroed(layout) {
            Ok(pointer) => pointer,
            Err(error) => handle_alloc_error(layout),
        };
        let opaque = rawu8.as_mut_ptr() as *mut ();
        let raw = ptr::from_raw_parts_mut::<Self>(opaque, num_words);
        let mut boxed = unsafe { Box::from_raw(raw) };
        boxed.cbSize = size_of::<SP_DEVICE_INTERFACE_DETAIL_DATA_W>() as u32;
        Ok(boxed)
    }

    pub fn layout_for(
        size: usize,
    ) -> Result<(Layout, usize, <[u16] as Pointee>::Metadata), InvalidBufferSize> {
        let cbsize = size_of::<SP_DEVICE_INTERFACE_DETAIL_DATA_W>() as u32;
        let layout_cbsize = Layout::for_value(&cbsize);
        let num_words = size.strict_sub(layout_cbsize.size()).strict_div(size_of::<u16>());
        let layout_devicepath = Layout::array::<u16>(num_words)?;
        let (layout_extended, offset) = layout_cbsize.extend(layout_devicepath)?;
        let layout = layout_extended.pad_to_align();
        (layout.size() == size)
            .ok_or_else(|| InvalidBufferSize::InvalidSize { requested: size, valid: layout.size() })?;
        Ok((layout, offset, num_words))
    }
}
```

### After (with `derive_dst`)

```rust
#![feature(default_field_values)]
#![feature(ptr_metadata)]
use derive_dst::DST;

#[repr(C)]
#[derive(Debug, PartialEq, Eq, DST)]
pub(crate) struct DeviceDetails {
    cbSize: u32 = size_of::<SP_DEVICE_INTERFACE_DETAIL_DATA_W>().strict_cast::<u32>(),
    DevicePath: [u16],
}

// `DeviceDetails::new(size)`, `DeviceDetails::layout_for(size)` and
// `InvalidDeviceDetails` are now generated by the derive.
```

## Requirements & contract

- **Nightly toolchain** (pinned via `rust-toolchain.toml`). Two nightly features are required in
  the crate *using* the derive:
  - `default_field_values` — for the `field: Type = expr` defaults in the struct declaration
  - `ptr_metadata` — for the generated `ptr::from_raw_parts_mut` call in `new`

  (The proc-macro crate itself additionally uses `proc_macro_diagnostic`, detected via
  [`build_safely`](https://crates.io/crates/build_safely), for rich compiler errors.)
- The annotated type must be a **struct with named fields** and **`#[repr(C)]`** (the whole point
  is a predictable, C-compatible layout).
- The **last field must be an unsized slice** `[T]`; only the last field may be unsized.
- Every other (sized) field must declare a **default value** `field: Type = expr`; `new`
  assigns these after allocating zeroed memory.

Misuse (wrong item kind, missing `repr(C)`, sized tail, missing defaults, ...) is reported with
rich, spanned compiler diagnostics via
[`proc_macro2_diagnostic`](https://github.com/MusicalNinjaDad/proc_macro2_diagnostic), and covered
by compile-fail tests (`tests/compilation/`).

## Safety

`new` allocates with `Global.allocate_zeroed` using the layout computed by `layout_for`, forms
the fat pointer with `ptr::from_raw_parts_mut` (thin data pointer + element count as metadata)
and boxes it. The layout is validated against the requested `size` before any allocation, so the
returned `Box<Self>` is always correctly sized, aligned and initialised.
